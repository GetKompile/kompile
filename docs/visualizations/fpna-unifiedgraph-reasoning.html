How SKU ⊑ Product changes resolution

A master-table row can begin with the declared type SKU. The ontology bridge exposes it as an individual; OWL RL follows the subclass closure and adds Product to its type memberships. The “product” dimension can then include GRO‑203 because of schema entailment—even when the literal word “product” never appears in the row label.

type(x, SKU) ∧ subClassOf(SKU, Product) ⇒ type(x, Product)

TableMemberOntologyBridge connects inferred table typing to the OWL schema. OwlRlReasoner performs subclass/type closure and writes inferred memberships such as owlInferredTypes.

Three sources form the closed resolution vocabulary

The resolver chooses from graph evidence rather than generating an unconstrained answer.

Explicit dimensionsValues already stamped on entities, such as region=AMER.
Tabular membersString cells beneath a named dimension column, such as Region → EMEA.
Typed table membersMember keys/labels whose declared or OWL-inferred memberships match the requested dimension.
user says “US” or “GRO‑203”→derive dimension key→closed candidate set ≤24→alias selection→typed entity / executable cell

This bounds alias resolution. Delimited alias rows are excluded from member discovery, preventing a synonym list from being mistaken for actual business members.

How types factor into resolving processes

Types affect four different parts of the process pipeline; they are not merely display metadata.

Candidate inclusionOnly entities/events compatible with an activity, control, exception, communication, or other process family enter that projection.
Taxonomy roll-upSpecific event types can roll up through parent types, reducing fragmentation while preserving the original leaf activity in provenance.
Rule bindingFOL and MEBN variables bind to entities satisfying declared or inferred type constraints, shrinking invalid grounding combinations.
Semantic coverageGold concepts and candidate activities match across subclass/alias boundaries, improving recall without relying on label overlap alone.
raw event: GRO‑203 adjustment→SKU + inferred Product→forecast-adjustment activity→variance / exception family→candidate process + typed trace
Ontology does not manufacture a process. It broadens valid membership, normalizes granularity, and constrains bindings. Topology, temporal/precedence relations, entailment, hybrid scores, and acceptance gates still determine whether the resulting candidate is ranked and accepted.

Code graph versus domain graph

code_graph answers how software symbols depend on one another. graph_search and GraphQueryEngine answer how business or knowledge entities relate. An agent should not treat these graphs as the same namespace.

Search versus reasoning

Search retrieves candidates. Reasoning evaluates relations, direction, type constraints, probabilities, paths, contradictions, and provenance. A high semantic match is evidence to inspect—not automatically a supported claim.

Worked example: an LLM answers with the graph

The LLM plans and narrates; the graph tools resolve identities, compute numbers, test claims, and supply provenance.

Why did July AMER gross profit fall, and how many DTC units would restore it?
Plan
1. Resolve AMER and July.
2. Find the executable gross-profit model.
3. Compare baseline and changed scenario.
4. Goal-seek controllable DTC units.
5. Return caveats and trace evidence.
Grounded answer
Gross profit fell by $211,491, from $2,383,302 to $2,171,810. Restoring it requires either HYD‑101 at 11,800 units (+6,120 after the cut) or RST‑001 at 27,623 (+14,099). Both scenarios reach the original $2,383,302 target.
1schema / vocabularyThe LLM asks what dimensions and members exist. The graph returns REGION=[AMER, EMEA, APAC] and typed product members.
2resolve aliases“AMER” resolves inside the bounded region vocabulary; “July” resolves to the July time slice. No unconstrained generation is accepted.
3executable modelRetrieval selects the synthesized weighted gross-profit rollup, with 10 candidates, 0 gaps, 9 interventions, and 27 plan rules.
4scenario executeThe graph computes baseline $2,383,302 and changed $2,171,810. The LLM does not perform or invent the arithmetic.
5goal seekThe solver targets $2,383,302 over 11 controllable quantities and returns SOLVED 11/11, including the two selected DTC scenarios.
6trace / explainFormula dependencies, resolved dimensions, interventions, controls, units, and limitations are rendered into LLM context.
What the LLM contributes

Intent decomposition, tool selection, clarification strategy, comparison of alternatives, concise language, and a response shaped for the user.

What the graph contributes

Canonical identities, ontology-backed types, bounded vocabularies, formulas, executable values, causal/dependency paths, confidence, gaps, and a reproducible trace.

natural language→tool plan→typed resolution→localized executable graph→scenario + goal seek→trace-grounded answer

Guardrail: if the graph lacked cost behavior, the tool result would expose the gap and the LLM should say the effect cannot be propagated. If resolution were ambiguous, the LLM should ask or present candidates. Tool evidence controls the claim; fluency does not upgrade UNKNOWN to SUPPORTED.

How a decision is made

The graph engine does not jump from a phrase to an answer. Each result is the product of explicit resolution, evidence selection, model choice, scoring, and trace construction.

1

Resolve intent

Choose overview, search, path, claim, similarity, rank, calculation, or goal seeking.

2

Resolve entities

Rank exact ids, labels, phrases, aliases, types, and candidate matches.

3

Select evidence

Direct relation, neighborhood, path, formulas, ontology, or grounded facts.

4

Choose engine

Direct graph, PSL, Bayesian/MEBN, FOL, embedding, or hybrid consensus.

5

Compute score

Blend weight, confidence, topology, semantic similarity, and learned weights.

6

Apply gates

Thresholds, scope limits, order support, oversized-candidate checks, contradictions.

7

Return trace

Status, answer, evidence, alternatives, missing facts, provenance, and guidance.

What the results do—and do not—prove

Process recall is not extraction perfection.

Regional submission is 62.5% concept recall, ontology evolution 75%, variance triage 87.5%, and monthly close order recall 77.8%. Candidate precision and duplicate granularity remain unevaluated.

Inference is bounded by graph evidence.

Missing vectors trigger structural fallback; absent cost behavior blocks downstream profit propagation; no direct relation yields UNKNOWN even when an indirect path exists; FOL grounding truncated at 10,000 pairs for a 2,097-entity graph.

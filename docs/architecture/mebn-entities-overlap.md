# MEBN ↔ Entities Overlap, and the Path to Probabilistic Facts with Learned Weights

**Date:** 2026-06-21
**Scope:** How much the MEBN subsystem and the "entities" model overlap, and a concrete path where a reasoning run emits **probabilistic facts (atom + probability) whose rule/relation weights are learned from data**.

---

## 1. Concept map (cited)

| MEBN (`graph-reasoning/mebn/`) | Entity model (`model/` + KG `domain/`) | Relationship |
|---|---|---|
| `EntityType.typeName` (`mebn/EntityType.java:24`) | `GraphEntity.type()` (`model/GraphEntity.java:38`) — free-form string | **Same thing**; `MebnInferenceService.buildSimpleTheory` (`fol/MebnInferenceService.java:141`) already builds an `EntityType` by filtering `graph.entities()` on `e.type()`. |
| `EntityType.entityIds` | the set of `GraphEntity.id()` of that type | **Same** — `EntityType` is an index over graph entities. |
| `EntityType.superType` | *(none on `GraphEntity`)* | **Divergence** — MEBN has explicit isA; `GraphEntity.type()` is flat (KG `OntologySchema` is a separate, unwired system). |
| `RandomVariable` (typed predicate + states + RESIDENT/INPUT/CONTEXT role) | *(no 1:1)* | **Complementary** — RVs are MEBN's first-class probabilistic schema; the KG expresses this only implicitly via edge types/attributes. |
| binary `RandomVariable` | `GraphRelation.type()` | **Partial** — RV carries a CPT + states; relation type is structural only. |
| `MFrag` (templates + context constraints) | *(none)* | **MEBN-only.** |
| SSBN (`SSBNGenerator.java:87`) → `BayesianNetwork` | `GraphBayesianNetworkBuilder` | **Convergent** — both ground a BN over KG nodes (systematic vs heuristic). |
| `MFrag.edgeStrengths` (noisy-OR scalars) | `GraphRelation.weight()` | **Analogous** — `KnowledgeGraphReasoningAdapter:114` maps edge weight→confidence→noisy-OR strength. |

**Overlap verdict:** ~40% redundant (`EntityType` ≈ a typed index over `GraphEntity` + an isA pointer; the `mebn/logic/KnowledgeBase` interface is now fully covered by `ReasoningGraphKnowledgeBase`), ~60% complementary (`RandomVariable`, `MFrag`, CPT machinery are genuinely MEBN-only). `EntityType` should become a **computed view** over `ReasoningGraph`, not a separately-maintained registry.

## 2. Current pipeline + where it breaks

- **PSL:** graph → `GraphPslProgramBuilder` → `HlMrfMapInference` → soft-truths. `EntailmentEngine.entailFromPsl()` already makes `EntailmentRecord`s, and `InferredFact.fromEntailment()` exists — **but nothing wires them into an `InferredFactStore` / `InferredFactGraphMaterializer`.**
- **MEBN:** graph → `MebnInferenceService.infer` → SSBN → `VariableElimination.queryAll` → posteriors. `EntailmentEngine.entailFromMebn()` exists — **same missing bridge to `InferredFact`.**
- **Weight learning (`learning/`):** `StructuredPerceptronLearner` / `PseudolikelihoodLearner` are complete and tested but **called nowhere in production** — learned `List<PslRule>` weights are never fed back into inference, never persisted, never attached to a fact.
- **Materialization (`reasoning/InferredFactGraphMaterializer` + REST):** complete, but only triggered by a **manual** POST — no automatic emission from an inference run.

## 3. Gaps
1. ✅ PSL result → `InferredFact` (Phase 1). 2. ✅ MEBN posterior → `InferredFact` (Phase 4). 3. ✅ Weight learning wired to inference (PSL Phase 2; MEBN Phase 7). 4. ✅ Learned-weight provenance on `InferredFact.ruleWeights()` (PSL Phase 3; MEBN Phase 7). 5. ✅ MEBN CPT learning (`MebnWeightLearner`, Phase 7) — was: `MFrag.edgeStrengths` hand-set. 6. `EntityType`/isA not wired to `OntologySchema` (deferred).

## 4. Phased path (reuses existing pieces)

- **Phase 1 — ✅ DONE (2026-06-21):** `FolInferenceService.inferFacts(graph, ruleSet)` and `inferFacts(graph, ruleSet, InferredFactStore)` now emit probabilistic `InferredFact`s (one per target atom: atomKey + posterior soft-truth as value/confidence + activated rules as provenance) and persist them. Implemented by extracting a precomputed-result core `EntailmentEngine.entailFromPslResult(program, result, factStore, runId)` (so the existing MAP result is reused — no double-solve) + reusing `InferredFact.fromEntailment`. The store side (`InferredFactGraphMaterializer` → INFERRED edges, REST endpoint) already existed, so a run can now go inference → facts → graph. Tested in `FolReasoningTest` (lib 314 green).
- **Phase 2 — ✅ DONE (2026-06-21):** `PslWeightLearningService` (lib `learning/`) wires the existing learners into production: `learn(program, groundTruth)` → learned `List<PslRule>`; `learnAndApply(...)` → a program with learned weights ready to infer (via new public `PslProgram.withRules(rules)` — rebuilds preserving atoms + arithmetic rules); `learnForGraph(FolInferenceService, graph, ruleSet, groundTruth)` (uses new public `FolInferenceService.buildProgram` — build without solving); `weightsToJson`/`parseWeights` persist learned weights (hand-rolled JSON, no jackson-databind). So: build program → learn weights from labels → apply → `inferFacts` → probabilistic facts produced under learned weights. Tested in `PslWeightLearningServiceTest` (lib 317 green).
- **Phase 3 — ✅ DONE (2026-06-21):** facts now carry their learned weights with **zero schema change**. The PSL rule display already prefixes the weight (`PslProgram.ground` → `"3.20: …"`), so when inference runs under a learned-weight program the weight already travels into each fact's `supportingRuleIds`. Added (a) `FolInferenceService.inferFacts(PslProgram)` so a learned-weight program can be inferred directly, and (b) the derived accessor `InferredFact.ruleWeights()` → `Map<ruleDisplay, learnedWeight>` (parses the weight prefix; skips hard rules). End-to-end test: `learnAndApply` → `inferFacts(program)` → facts whose `ruleWeights()` expose the learned weights (lib 319 green).
- **Phase 4 — ✅ DONE (2026-06-21):** `MebnInferenceService.inferFacts(graph, theory, FindingStore[, InferredFactStore])` emits probabilistic `InferredFact`s from MEBN posteriors (atomKey = grounded RV `rv(entityId)`, value = posterior P(TRUE)), reusing `EntailmentEngine.entailFromMebn` + `InferredFact.fromEntailment`. So the **PSL and MEBN paths now feed the same `InferredFact` sink** → persist (`InferredFactStore`) → materialize (`InferredFactGraphMaterializer` → INFERRED edges). Atom keys are already `Pred(entityId)` so the materializer parses them unchanged. MEBN facts carry no rule weights (MEBN uses CPTs, not weighted rules — CPT learning remains Gap 4). Tested in `FolReasoningTest$MebnTests` (lib 321 green).
- **Phase 7 — ✅ DONE (2026-06-21):** **MEBN facts with learned weights** (closes Gap 5, the "great extension"). `MebnWeightLearner` (lib `learning/`) fits MEBN noisy-OR `MFrag.edgeStrengths` to observed grounded-RV targets by **batch finite-difference gradient descent** (treats SSBN-generation + variable-elimination as a black-box loss; reuses existing MEBN machinery, no analytic noisy-OR gradient). Enabled by `MFrag.setEdgeStrength(parent, child, strength)` (in-place update). The learnable theory shape is the new `MebnInferenceService.buildCausalTheory(graph, typeName, causeRv, effectRv, strength)` — a per-entity `effect(X) ← cause(X)` noisy-OR whose child the SSBN actually grounds (so its posterior is strength-sensitive). Learned strengths then **travel onto MEBN facts**: `EntailmentEngine.entailFromMebn` populates each fact's `supportingRuleIds` with `"<strength>: parent->child"` (matched by predicate), so `InferredFact.ruleWeights()` surfaces MEBN CPT strengths exactly as it does PSL rule weights. Tested in `MebnWeightLearnerTest` (3 tests: loss-reduction + strength-rise, end-to-end ruleWeights match, no-edge no-op) — lib 324 green.
  - ⚠️ **Finding:** `buildPropagationTheory` (relational `isActive(Y) ← isActive(X)` gated by `edge(X,Y)`) is **inert** — its context constraint references vars `X`/`Y` but `SSBNGenerator.processMFrag` only binds positional keys (`Person_0`, `Person`), so `edgeOfType("X","Y",…)` always sees `null`/`null` and the propagation child never instantiates (only the root priors ground). Cross-entity relational grounding needs a deeper SSBNGenerator fix (positional→named var binding); out of scope here. `buildCausalTheory` (per-entity, no relational context) sidesteps it.
- **Phase 5 (unification):** `EntityType.fromGraph(ReasoningGraph, typeName)` — make `EntityType` a live view, collapsing the ~40% redundancy.
- **Phase 6 (deferred):** wire `OntologySchema` isA → `EntityType.superType`.

**✅ ACHIEVED — "probabilistic facts with learned weights" (Phases 1+2+3 done).** End-to-end: `buildProgram(graph, ruleSet)` → `PslWeightLearningService.learnAndApply(program, groundTruth)` → `FolInferenceService.inferFacts(learnedProgram)` → each `InferredFact` has `value()` (probability) + `ruleWeights()` (the learned weights that produced it), persistable via `InferredFactStore` and materializable to `INFERRED` graph edges. Remaining (optional): Phase 4 (MEBN posterior → InferredFact via `entailFromMebn`), Phase 5 (collapse `EntityType` into a `ReasoningGraph` view).

# UI persona boundary

Companion to `app-persona-boundary.md`, which does the same job for the 154 controllers.
Generated by a transitive closure over the Angular component graph: start at each persona's
route-root components, walk every TS import of a sibling component and every template
selector usage to a fixpoint. A component reached by more than one persona goes to the
shared library; a component reached by exactly one goes to that app.

`AppComponent` is a root for all three personas — each app carves its own shell from it, so
the chrome it pulls in (branding, status indicators) is shared by construction.

## The graph split

`GraphsHubComponent` is standalone and eagerly `imports:` all 29 panels, so routing an
end-user app at it would pull the whole maintenance/rules/health/simulator/OWL suite into
that bundle — section-gating alone cannot prevent it. Chat and crawl therefore route at an
explore-only hub carrying `SECTION_TABS.explore` (visualizer, hierarchy, overview,
communities); admin keeps the full `GraphsHubComponent` unchanged. This is what the approved
plan means by "Read-only exploration ... Maintenance/rules/health/simulator/OWL stay admin".

## Totals

| Project | Components |
|---|---|
| `kompile-ui-shared` | 38 |
| `admin-app` | 113 |
| `crawl-app` | 73 |
| `chat-app` | 6 |
| _unreachable from any route root_ | 19 |

All 179 services and 33 models go to `kompile-ui-shared`. Angular tree-shakes
`providedIn: 'root'` services that nothing injects, so an admin-only service in the library
does not ship in an end-user bundle.
